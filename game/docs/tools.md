# Tools

Details of the `npm run` commands and debug tools. Run them from `game/`.

## Commands

- `npm run playtest` boots the game in headless Chromium on the GPU, plays turns, and fails on page errors, the crash screen or low FPS. The GPU is Metal on a Mac and Vulkan on Linux. It fails when Chromium falls back to software drawing. It needs the dev server running, at `--url` or the default port. Screenshots go to `.playtest/`. `--cpu` draws in software, skips the FPS check, plays 4 turns and gives each turn 60 seconds. Use it on machines without a GPU.
- `TEST_TIMEOUTS=off` removes every time limit from `npm test` and `npm run playtest`. The factory sets it on its shared server, where a slow test is load, not a hang. There the factory's job time limit stops a hung run.
- `npm run combat -- --enemies buggy,gunwagon,buggy+buggy --policy all --seeds 1-20` plays fights on flat open ground through the real turn pipeline and physics. The player truck stands, circles, charges or kites with auto fire. A kiting truck closes to near its longest gun range, then backs away nose first toward the foe, and NPCs run their own brains. It writes outcomes, hit rates and damage per lineup and policy to `tmp/combat/`. `--set RULES.leadError=3` changes one balance number for the run, so a tuning idea is measured before any code changes. `--trace` prints every turn.
- `npm run icons -- [--cpu] [--plans]` renders every part, good and chassis icon from the game's models in headless Chromium through the dev-only `icons.html`. It writes the sprite sheets in `public/icons/`, the condition panel's `tint.svg` and `plans.svg`, the manifest `src/data/item-icons.json`, and the labeled atlases and closest-pairs report in `public/icons/atlas/`. It fails when a weapon barrel does not read from lower left to upper right in the diagonal view. It prints each failing entry first. `--cpu` draws in software, as `playtest` does, and takes under a minute. `--plans` writes only `plans.svg`. [Art pipeline](art.md#icons) has the rules.
- `npm run stuck` is the progression recorder with a trader bot, seeds 1 to 3 and 1000 turns, each seed in its own process, one at a time. It fails on any error, watchdog stall from any truck, or majority of NPCs dry at once, and prints the stall with the driver's goals, order, route and neighbors. It takes about a minute. Override the arguments after `--`, as for `progression:record`.
- `npm run traffic -- --seeds 1-3 --turns 300 --layer physics|far` plays a world of NPCs with the player parked and measures how fast trucks drive on the road, in km/h of the path driven each turn. The `physics` layer drives every NPC in Rapier and the `far` layer uses far travel only. It reports steady cruise per class (healthy ordinary cars, ordinary cars on low fuel, worn ordinary cars, armed and heavy roles, towing rigs) and per chassis, the causes of slow healthy samples, the low-fuel share, resupply starts, the most NPCs dry at once and collisions. It writes `tmp/traffic/<layer>-seed-<n>.json` and `tmp/traffic/<layer>.md`. Three seeds take about 13 minutes for physics at 300 turns and 10 for far at 800 turns.
- `npm run save:shape` records the saved shape of the current save format in `src/three/save-shape.json`.
- `npm run wiki` regenerates the tables in `docs/wiki/` from the code. A test fails when a table is stale or wiki prose names a data path or source file that no longer exists.
- `npm run loadouts -- --rolls 60 [--template merc] [--level heavy]` rolls many NPC loadouts per template and prints the gear level mix, guns, armor cover, cab cover, gear value, mass and cargo value. It writes `tmp/loadouts.md`. A test keeps each template's averages inside the `targets` bands of its loadout table.
- `npm run map:bake` builds the map from `MAPGEN.seed` in `src/data/terrain.ts` and writes `public/maps/icarus.bin`. It also writes a whole-map picture and close-ups to `tmp/map/`. A save made on another map does not load. Boot then offers to carry the player over, as [Saves](architecture/saves.md) describes, so a new map file needs no major save bump.
- `npm run perf -- --url <dev server>` boots the game in Chromium with the Metal GPU and times boot, turns, move previews, frames and the per-frame work of automatic travel. It fails on any miss against `scripts/perf-budgets.json`.
- `npm run sfx:board` opens the dev sound board for auditioning every cue.
- `npm run sfx:import -- <cue> <file...>` imports files as variants of a cue in `src/data/sounds.ts`.
- `npm run sfx:gen -- <cue> <count>` generates variants with ElevenLabs. It costs credits.
- `npm run sfx:reimport` rebuilds every sound file from the raw source path stored in its tags, after an import change.
- `npm run progression:record -- --archetypes trader,scavenger,hunter,fastTrader --seeds 1,2,3 --turns 2000` plays a bot per archetype and seed and writes each trace to `tmp/progression/` or to the `--out` directory: the XP events and one economy row per in-game day. Every bot earns, pays upkeep, buys gear and shoots back. In town it tops up the parts good to the standard kit's stock before it buys gear, so a breakdown gets a field patch. It hands its cargo to a demand, or its gear to a strip offer, only when the foe outmatches it. A bot parks when its engine reaches the heat warning and stays parked until the engine is at half of it, except in combat or with a hostile in sight. A stranded bot leaves its rescue beacon off in combat. A bot judges whether it outruns a foe by its truck's speed as it stands, so a stranded or crippled truck outruns nothing. A bot inside a raider camp's gun range drives straight out of it, and the hunter never chases a foe inside one. Only the hunter seeks fights. While no raider in the world is weak enough for it to fight, it scavenges instead. It buys gear only while it keeps free the cells of the biggest part and the top speed of the fastest raider it would fight. It takes a bounty, and chases a foe it only hears, only when the foe's worst-case danger times 4 is within its own. The `hauler` takes the best haul contract on every board it reads and trades only with none, so it measures what contracts pay against open trade. The `climber` plays the snowball a player described: it hauls and scavenges until the truck mounts three guns, then hunts like the hunter. `--kit snowball` starts from that player's convertible with four guns. The `markov` archetype plays a random one of the others and needs `--markov-turns <k>`, the turns it keeps one goal. `--kit combat` starts every run from that start kit, such as the geared combat kit, instead of the standard one. The recorder runs headless, so every truck uses the cheap far rules. Runs go one at a time. A run that hits an error ends with an error line, the next run starts, and the batch fails at the end. A 30-day run takes about 18 minutes, so run it in the background with a log.
- `npm run progression:report` replays every trace in `tmp/progression/` with the current XP rules. It prints the days each activity family's XP covers each rank's cumulative cost, the XP per day per archetype and misses against the targets in `src/data/skills.ts`. It also prints, per archetype, the wage per turn at each gear tier, the first day each tier is held, and the fights won, knockouts, gear lost and deaths of each seed, net worth by day split into money, cargo, gear, storage and chassis, and money by ledger key. Net worth counts truck damage at its repair bill. Goods a haul contract carries are not counted, so accepting and delivering a haul moves net worth only by what it pays. A last summary prints one line per bot with profit per turn, net worth gained per turn and its ratio to the trader. Profit is every ledger key but gear, so it measures the work and not the shopping. Goods still aboard at the end count as spent. Pass a directory after `--` to report on traces elsewhere. Pass two directories to compare them: each bot's summary on side A and side B, and the change in money per day by ledger key.
- An A/B test checks a balance change before it goes into `src/data/`. Write a patch module that imports a data file and changes a number in place, such as `DISTANCE_PREMIUM.perTile *= 2`. Record the same bots, seeds and turns twice, once plain into one `--out` directory and once with `--patch <file>` into another, then report on both directories. A number a data file derives from another at load time does not follow the patch, so patch it as well. The report says so when both sides end on the same net worth.
- `npm run progression:watch -- --archetype trader --seed 1 --from 4500 --to 5000` plays one run and prints the player truck turn by turn: money, net worth, goods, contracts, order, part HP and the events that touch the player. Use it to see why a number in the report looks wrong.
- Beside each trace the recorder writes two logs for analysis by plain file reads. `<bot>-<seed>.turns.jsonl` has one line per turn: the player truck's position, money, net worth, fuel, parts with health, goods, contracts, order, flags, the hostiles in sight with their danger and speed, the money moved by kind, and every event that touches the player. `<bot>-<seed>.world.jsonl` has every event of every turn raw, whoever it touches, and a snapshot of every truck every 10 turns with its goals and states. A 5-day run writes about 7 MB. `npm run progression:analyze -- tmp/<dir>` sweeps a batch for every kind of trouble at once: time spent in combat, stranded or towed, each fight with the foes and the outcome, with each foe's danger and speed from the turn it first appears, combat stretches with no shot fired as one standoff line, each big loss with the events before it, tows, stalls, debt, dry tanks, flapping rules, the population per faction and every lost truck. Mine a batch fully before rerunning anything.
- `npm run itch` builds the game and uploads it to itch.io with butler. It builds the last commit in a clean worktree and names the upload after it. [Publishing](publishing.md) has the one-time setup.

## Config

`src/config.ts` holds the world seed, start kit, combat playback times, save interval, automatic turn delay, Space hold delay and travel speed multiplier. The world seed drives sim randomness, like where the first NPCs start, but not the map. A null seed rolls a new one for each new game, and the save keeps it. `.env` holds `ELEVENLABS_API_KEY` and `SFX_MAX_GENERATIONS` for sound generation and `ITCH_TARGET` and `BUTLER_API_KEY` for publishing.

## Browser checks

A browser check is for what the screen shows: UI, rendering and screenshots. Playtest game behavior with the progression recorder instead. Drive the game with a Playwright script in `tmp/`. Launch Chromium with `--use-angle=metal --enable-gpu --ignore-gpu-blocklist`, so it renders on the real GPU. On Linux with an NVIDIA card, use `--use-angle=vulkan --enable-features=Vulkan --disable-vulkan-surface --enable-gpu --ignore-gpu-blocklist`. SwiftShader renders on the CPU at 10 to 20 fps, so its frame rate says nothing about the game. The game is on `window.__ROAM__` in dev. Its world is `__ROAM__.state`. To set up a situation, clone that world, edit it, and pass it to `apply()`. `debugScreenOf(x, y)` gives the screen point of a map point on the ground, for clicks. `node scripts/garage-ui-check.mjs <url>` checks the garage: mouse and keyboard selection drives the shop comparison, the garage header and repair bar labels, and the layout at 1280, 1024 and 800 wide.

## Debugging

- In dev, any uncaught error shows a fullscreen crash screen with the message. Outside dev, errors after boot go to the browser log and the debug console, and the game keeps running. Boot errors always show the crash screen. A failed turn does not play: the log shows it, automatic turns stop, and no save is written until a turn completes without an error.
- The backquote or § key opens the debug console in every build. Type `help` for its cheat commands. `src/ui/console.ts` parses the commands and calls one pure function per cheat in `src/sim/cheats.ts`. Bad input throws `CheatError`, which the console prints. Any other error reaches the crash screen. God mode is a saved player flag. It restores the truck in `endTurn` before the destruction and defeat checks.
- `src/perf.ts` holds named timers for seams, never hot loops, and merges worker measurements into the main counters. The console command `fps` shows them in a panel in the top left.
