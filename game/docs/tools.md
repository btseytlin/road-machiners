# Tools

Details of the `npm run` commands and debug tools. Run them from `game/`.

## Commands

- `npm run playtest` boots the game in headless Chromium on the GPU, plays turns, and fails on page errors, the crash screen, a missing or zero-size game canvas, a run that ends short of its turns, a HUD panel made of one control that misses a click at a corner of the panel, or a frame rate under 50. The GPU is Metal on a Mac and Vulkan on Linux. It fails when Chromium falls back to software drawing. It needs the dev server running, at `--url` or the default port. Screenshots go to `.playtest/`. `--turns <n>` sets the turns to play, 12 by default, and each turn gets 10 seconds. `--no-fps-gate` keeps the GPU run but only prints the FPS. The factory uses it everywhere but the release candidate, since its host runs many jobs at once. `--cpu` draws in software, skips the FPS check, plays 4 turns and gives each turn 60 seconds. Use it on machines without a GPU.
- `npm run ui-playtest` checks the HUD layout in headless Chromium: the readouts, the instruments and clock, the event log, the radio and its knobs, the right column, the weapons dock, modal frames and inventory inspection, at several viewport sizes. It needs the dev server at the default port, `http://localhost:5173`. Screenshots go to `.playtest/`. `CPU=1` drops the GPU flags and gives each step 180 seconds. `DOCK_ONLY=1` checks the weapons dock only.
- `TEST_TIMEOUTS=off` removes every time limit from `npm test` and `npm run playtest`. The factory sets it on its shared server, where a slow test is load, not a hang. There the factory's job time limit stops a hung run.
- `TEST_WORKERS=<n>` sets how many workers Vitest runs at once. Without it, Vitest runs one per CPU, up to 6. The factory sets it per container, so the test runs of all its jobs fit the server's memory.
- `npm run combat -- --a merc,merc:snowball --b buggy,buggy:buggy@heavy,buggy+buggy --seeds 1-5` plays fights between two sides on flat open ground through the real turn pipeline and physics. Every lineup of `--a` fights every lineup of `--b`, and `+` joins trucks in one lineup. A truck is `driver:gear`. The driver is an NPC template, whose brain drives the truck. The gear is a start kit, an NPC template's rolled loadout as `buggy` or `buggy@heavy`, or `mg/plates+ram` for one gun and one armor on a hauler, with `bare` for no armor. A driver without gear takes its own template's loadout. To tune gear, keep the driver and vary the gear. To tune behavior, keep the gear and vary the driver. A scripted driver, `stand`, `orbit`, `charge` or `kite`, steers the player truck instead, alone on side a, to test one way of driving. `--arena 9` rings the fight with rocks 9 tiles out. The arena resumes hostility after a truce or surrender, so survivors keep fighting until a knockout or the turn limit. The ring must fit in sight, so 10 tiles at most. An arena allows 400 turns by default because evenly matched buggies took 283, versus 40 turns on open ground. It writes outcomes, hit rates and damage per pair of lineups to `tmp/combat/`, and names the side that fled. `--set RULES.leadError=3` changes one balance number for the run, so a tuning idea is measured before any code changes. `--trace` prints every turn.
- `npm run icons -- [--cpu] [--plans]` renders every part, good and chassis icon from the game's models in headless Chromium through the dev-only `icons.html`. It writes the sprite sheets in `public/icons/`, the condition panel's `tint.svg` and `plans.svg`, the manifest `src/data/item-icons.json`, and the labeled atlases and closest-pairs report in `public/icons/atlas/`. It fails when a weapon barrel does not read from lower left to upper right in the diagonal view. It prints each failing entry first. `--cpu` draws in software, as `playtest` does, and takes under a minute. `--plans` writes only `plans.svg`. [Art pipeline](art.md#icons) has the rules.
- `npm run stuck` is the progression recorder with a trader bot, seeds 1 and 2 and 500 turns, each seed in its own process, one at a time. It fails on any error, watchdog stall from any truck, or majority of NPCs dry at once, and prints the stall with the driver's goals, order, route and neighbors. It takes about 2 minutes. Override the arguments after `--`, as for `progression:record`.
- `npm run traffic -- --seeds 1-3 --turns 300 --layer physics|far` plays a world of NPCs with the player parked and measures how fast trucks drive on the road, in km/h of the path driven each turn. The `physics` layer drives every NPC in Rapier and the `far` layer uses far travel only. It reports steady cruise per class (healthy ordinary cars, ordinary cars on low fuel, worn ordinary cars, armed and heavy roles, towing rigs) and per chassis, the causes of slow healthy samples, the low-fuel share, resupply starts, the most NPCs dry at once and collisions. It writes `tmp/traffic/<layer>-seed-<n>.json` and `tmp/traffic/<layer>.md`. Three seeds take about 13 minutes for physics at 300 turns and 10 for far at 800 turns.
- `npm run save:shape` records the saved shape of the current save format in `src/three/save-shape.json`.
- `npm run wiki` regenerates the tables in `docs/wiki/` from the code. A test fails when a table is stale or wiki prose names a data path or source file that no longer exists.
- `npm run loadouts -- --rolls 60 [--template merc] [--level heavy]` rolls many NPC loadouts per template and prints the gear level mix, guns, armor cover, cab cover, gear value, mass and cargo value. It writes `tmp/loadouts.md`. A test keeps each template's averages inside the `targets` bands of its loadout table.
- `npm run map:bake` builds the map from `MAPGEN.seed` in `src/data/terrain.ts` and writes `public/maps/icarus.bin`. It also writes a whole-map picture and close-ups to `tmp/map/`. A save made on another map does not load. Boot then offers to carry the player over, as [Saves](architecture/saves.md) describes, so a new map file needs no major save bump.
- `npm run perf -- --url <dev server>` boots the game in Chromium on the GPU and times boot, turns, move previews, frames over the towns by day and at night, and the per-frame work of automatic travel. It fails on any miss against `scripts/perf-budgets.json` and when Chromium falls back to software drawing. `scripts/gpu.mjs` holds the GPU flags for the playtest, perf, icons and UI playtest scripts.
- `npm run sfx:board` opens the dev sound board for auditioning every cue.
- `npm run sfx:import -- <cue> <file...>` imports files as variants of a cue in `src/data/sounds.ts`.
- `npm run sfx:gen -- <cue> <count>` generates variants with ElevenLabs. It costs credits.
- `npm run sfx:reimport` rebuilds every sound file from the raw source path stored in its tags, after an import change.
- `npm run progression:record -- --archetypes trader,scavenger,hunter,fastTrader --seeds 1,2,3 --turns 2000` plays a bot per archetype and seed and writes each trace to `tmp/progression/` or to the `--out` directory: the XP events and one economy row per in-game day. Every bot earns, pays upkeep, buys gear and shoots back. In town it tops up the parts good to the standard kit's stock before it buys gear, so a breakdown gets a field patch. It hands its cargo to a demand, or its gear to a strip offer, only when the foe outmatches it. A bot parks when its engine reaches the heat warning and stays parked until the engine is at half of it, except in combat or with a hostile in sight. A stranded bot leaves its rescue beacon off in combat. A bot judges whether it outruns a foe by its truck's speed as it stands, so a stranded or crippled truck outruns nothing. Only the hunter seeks fights. Combat is not for a starter truck, so the hunter starts from the snowball kit unless `--kit` names another. While no raider in the world is weak enough for it to fight, it scavenges instead. It buys gear only while it keeps free the cells of the biggest part and the top speed of the fastest raider it would fight. It takes a bounty, and chases a foe it only hears, only when the foe's worst-case danger times 4 is within its own. The `hauler` takes the best haul contract on every board it reads and trades only with none, so it measures what contracts pay against open trade. The `climber` trades and buys fighting gear while keeping money for loads. Once it mounts three guns, it hunts weaker prey, accepts truces and mercy to limit repair costs, collects nearby knocked-out trucks before leaving for repairs, and trades between fights. `--kit snowball` starts from that player's convertible with four guns. The `markov` archetype plays a random one of the others and needs `--markov-turns <k>`, the turns it keeps one goal. `--kit combat` starts every run from that start kit, such as the geared combat kit, instead of the standard one. `--settings damage=2,fuelUse=1.5` starts every run in a Roaming world with those [world settings](wiki/mechanics/world-settings.md), each missing one at 100%, and a bad value fails the run. The recorder runs headless, so every truck uses the cheap far rules. Runs go one at a time. A run that hits an error ends with an error line, the next run starts, and the batch fails at the end. A 30-day run takes about 18 minutes, so run it in the background with a log.
- `npm run progression:report` replays every trace in `tmp/progression/` with the current XP rules. It prints the days each activity family's XP covers each rank's cumulative cost, the XP per day per archetype and misses against the targets in `src/data/skills.ts`. It also prints, per archetype, the wage per turn at each gear tier, the first day each tier is held, and the fights won, knockouts, gear lost and deaths of each seed, net worth by day split into money, cargo, gear, storage and chassis, and money by ledger key. Net worth counts truck damage at its repair bill. Goods a haul contract carries are not counted, so accepting and delivering a haul moves net worth only by what it pays. A last summary prints one line per bot with profit per turn, net worth gained per turn and its ratio to the trader. Profit is every ledger key but gear, so it measures the work and not the shopping. Goods still aboard at the end count as spent. Pass a directory after `--` to report on traces elsewhere. Pass two directories to compare them: each bot's summary on side A and side B, and the change in money per day by ledger key.
- An A/B test checks a balance change before it goes into `src/data/`. Write a patch module that imports a data file and changes a number in place, such as `DISTANCE_PREMIUM.perTile *= 2`. Record the same bots, seeds and turns twice, once plain into one `--out` directory and once with `--patch <file>` into another, then report on both directories. A number a data file derives from another at load time does not follow the patch, so patch it as well. The report says so when both sides end on the same net worth.
- `npm run progression:watch -- --archetype trader --seed 1 --from 4500 --to 5000` plays one run and prints the player truck turn by turn: money, net worth, goods, contracts, order, part HP and the events that touch the player. Use it to see why a number in the report looks wrong.
- `npm run progression:playthrough -- --seed <n> --turns <n> --out <file> [--archetype markov] [--every 50] [--sha <sha>]` plays one progression run and writes its full activity log: every game event, a snapshot of the player and every NPC every `--every` turns, how the run ended, and a summary. `--archetype` defaults to `markov` and `--sha` to none. Every truck uses the cheap far rules, as in the recorder. The factory's release playtest reads the log. The log goes to a part file that is renamed when the run ends. A bad argument exits 1. An in-game error or stall ends the log with an error line and exits 0.
- Beside each trace the recorder writes two logs for analysis by plain file reads. `<bot>-<seed>.turns.jsonl` has one line per turn: the player truck's position, money, net worth, fuel, parts with health, goods, contracts, order, flags, the hostiles in sight with the player's odds to win against each and their speed, the money moved by kind, and every event that touches the player. `<bot>-<seed>.world.jsonl` has every event of every turn raw, whoever it touches, and a snapshot of every truck every 10 turns with its goals and states, whether it keeps off roads and whether it stands on one. A 5-day run writes about 7 MB. `npm run progression:analyze -- tmp/<dir>` sweeps a batch for every kind of trouble at once: time spent in combat, stranded or towed, each fight with the foes and the outcome, with the player's odds against each foe and its speed from the turn it first appears, combat stretches with no shot fired as one standoff line, each big loss with the events before it, tows, stalls, debt, dry tanks, flapping rules, the population per faction, how often raiders that keep off roads are on one against healthy raiders with a miss when hunting raiders are on a road more than 25% of the time, and every lost truck. Mine a batch fully before rerunning anything.
- `npm run income -- --seeds 1-6 --days 2 --policy robber,convoyRobber,trader,scavenger --jobs 3 --candidate A` plays each policy on the `midgame` start kit, every skill at rank 2 and no gear bought, through the real turn pipeline with every truck on far travel, one process per seed and policy. `robber` demands cargo from traders and convoys it sees carrying cargo with no escort in sight, and patrols Bowl and Nose. `convoyRobber` also takes on guarded convoys, and patrols the sites supply convoys haul between. Each run writes `tmp/income/<candidate>/<seed>-<policy>.json` (`--out` sets the folder) with the candidate name and the build: the last commit that changed non-test code in `src/`, plus a hash of any uncommitted change there. A run whose file exists for the same build is skipped, and one for another build fails the batch. Every 30 turns a run samples the world: the hauling margin index (the best load for 2000 money and 20 cells between two towns, less its fuel), the salvage price index (the mean town sell price of goods), and each awake trader and convoy's wallet, escort, cargo value and whether the robber would take it, sight aside. It also counts NPC knockouts and tows per day. The batch writes `report.md` in the folder with net worth per in-game hour, daily percentiles, robbery attempts by target and answer, and wallets by day. It throws when a run's money ledger does not match its money change. A 2-day run takes about 10 minutes of one CPU core, and several times that on a loaded host.
- `npm run income -- --report tmp/income/A --baseline tmp/income/baseline` writes only the report: the gate report of issue 157 (G1 to G7, with the robber and hauler paired by seed and the 80% interval of their difference) and the run tables. The gate thresholds are constants in `src/sim/progression/income-report.ts`, and a gate fails loud on runs of mixed builds.
- `npm run itch` builds the game and uploads it to itch.io with butler. It builds the last commit in a clean worktree and names the upload after it. [Publishing](publishing.md) has the one-time setup.

## Config

`src/config.ts` holds the world seed, start kit, combat playback times, save interval, automatic turn delay, Space hold delay and travel speed multiplier. The world seed drives sim randomness, like where the first NPCs start, but not the map. A null seed rolls a new one for each new game, and the save keeps it. `.env` holds `ELEVENLABS_API_KEY` and `SFX_MAX_GENERATIONS` for sound generation and `ITCH_TARGET` and `BUTLER_API_KEY` for publishing.

## Browser checks

A browser check is for what the screen shows: UI, rendering and screenshots. Playtest game behavior with the progression recorder instead. Drive the game with a Playwright script in `tmp/`. Launch Chromium with `gpuArgs()` from `scripts/gpu.mjs`, so it renders on the real GPU on a Mac and on Linux. SwiftShader renders on the CPU at 10 to 20 fps, so its frame rate says nothing about the game. The game is on `window.__ROAM__` in dev. Its world is `__ROAM__.state`. To set up a situation, clone that world, edit it, and pass it to `apply()`. `debugScreenOf(x, y)` gives the screen point of a map point on the ground, for clicks. `node scripts/garage-ui-check.mjs <url>` checks the garage: mouse and keyboard selection drives the shop comparison, the garage header and repair bar labels, and the layout at 1280, 1024 and 800 wide. `node scripts/shop-parts-check.mjs <url>` checks the compact shop part rows: collapsed by default, one open at a time, keyboard, purchase, filter and narrow layouts, with screenshots in `.playtest/`.

The game camera has a fixed bearing, so a shot of a face it does not show needs the camera turned from the script. The rig sets the camera at its fixed offset every frame, so wrap the instance's `tick` on `__ROAM__.rig`: call the original, then move `rig.camera.position` around `rig.center` to the bearing and elevation wanted at the same distance, and `lookAt(rig.center)`. The turn is script-only and never touches game code.

## Debugging

- In dev, any uncaught error shows a fullscreen crash screen with the message. Outside dev, errors after boot go to the browser log and the debug console, and the game keeps running. Boot errors always show the crash screen. A failed turn does not play: the log shows it, automatic turns stop, and no save is written until a turn completes without an error.
- The factory's release, dev and candidate builds also send every error to the factory's error endpoint, set by `ERROR_REPORT_URL` at build time. `src/three/error-report.ts` sends each distinct error once per session, with the world in memory, the Autosave, the log and, for a failed turn, the physics drive the turn started from. A build without the URL sends nothing.
- `npm run error:replay -- <report.json.gz>` reruns the turn of an error report headless and prints what it throws. Run it on the report's commit. `--from autosave` starts from the report's Autosave. Only a failed turn's report reruns exactly, since only it holds the physics drive.
- The backquote or § key opens the debug console in every build. Type `help` for its cheat commands. `src/ui/console.ts` parses the commands and calls one pure function per cheat in `src/sim/cheats.ts`. Bad input throws `CheatError`, which the console prints. Any other error reaches the crash screen. God mode is a saved player flag. It restores the truck in `endTurn` before the destruction and defeat checks.
- `src/perf.ts` holds named timers for seams, never hot loops, and merges worker measurements into the main counters. The console command `fps` shows them in a panel in the top left.
