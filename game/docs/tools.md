# Tools

Details of the `npm run` commands and debug tools. Run them from `game/`.

## Commands

- `npm run playtest` boots the game in headless Chromium on the GPU, plays turns, and fails on page errors, the crash screen, a missing or zero-size game canvas, a run that ends short of its turns, a HUD panel made of one control that misses a click at a corner of the panel, or a frame rate under 50. It also picks Russian by keyboard alone through Menu → Options → Language, checks that game keys wait while Options is open, and picks English back by mouse after a reload. It fails on any language control outside the Options panel. The GPU is Metal on a Mac and Vulkan on Linux. It fails when Chromium falls back to software drawing. It needs the dev server running, at `--url` or the default port. Screenshots go to `.playtest/`. `--turns <n>` sets the turns to play, 12 by default, and each turn gets 10 seconds. `--no-fps-gate` keeps the GPU run but only prints the FPS. The factory uses it everywhere but the release candidate, since its host runs many jobs at once. `--cpu` draws in software, skips the FPS check, plays 4 turns and gives each turn 60 seconds. Use it on machines without a GPU.
- `npm run ui-playtest` checks the HUD layout in headless Chromium: the readouts, the instruments and clock, the event log, the radio and its knobs, the right column, the weapons dock, modal frames and inventory inspection, at several viewport sizes. It needs the dev server at the default port, `http://localhost:5173`. Screenshots go to `.playtest/`. `CPU=1` drops the GPU flags and gives each step 180 seconds. `DOCK_ONLY=1` checks the weapons dock only.
- `npm run boot:check -- [--url ...] [--cpu]` checks the boot screen in headless Chromium at 1280x800 and 390x844: a fresh game, a saved game, the save rescue screen, the start menu, a failed map, a failed game module, a dropped and a lost model, and a dropped and a lost turn worker script. `--only startMenu` runs one case. It needs the dev server. Screenshots go to `.playtest/boot-*.png`. It takes several minutes with `--cpu`.
- `npm run boot:time -- [--url http://localhost:4173/] [--runs 5] [--viewport wide|narrow] [--net none|4g]` times time to playable in headless Chromium on the GPU: a fresh game on a cold cache, then a reload of the same context for a saved world on a warm cache. It prints the median and max of `roam:ready`, the boot screen clearing, each boot step and the code, map, model and sound fetch spans. `--net 4g` throttles to 10 Mbit/s with 40 ms latency. Run it against `npm run build && npx vite preview` for production numbers, and compare runs only on the same host. It only measures and does not fail on budgets.
- `TEST_TIMEOUTS=off` removes every clock time limit from `npm test` and `npm run playtest`. The factory sets it on its shared server, where a slow test is load, not a hang, and the full suite on GitHub Actions sets it too. There the stall watch and the job time limit stop a hung run.- `TEST_SUITE_MINUTES` stops a `test:cached` run that runs longer and fails it with its slowest finished files. The full suite on GitHub Actions sets 20.
- `TEST_WORKERS=<n>` sets how many workers Vitest runs at once. Without it, Vitest runs one per CPU, up to 6. The factory sets it per container, so the test runs of all its jobs fit the server's memory.
- The full suite keeps its run time down by sharing setup between tests. A Vitest global setup builds the empty test world once per run and `emptyWorld()` copies it. Tests that need a full start world call `standardWorld(seed)` or `reusedWorld(key, build)` from `src/test/world-cache.ts`, which build it once per file and hand out copies. Copy worlds with `cloneWorld`, never `structuredClone`, so a frozen terrain stays shared and its nav layers are not rebuilt each turn. `editableTerrain()` returns a frozen terrain object whose `heights` and `types` arrays a test can still edit in place.
- `npm run combat -- --a merc,merc:snowball --b buggy,buggy:buggy@heavy,buggy+buggy --seeds 1-5` plays fights between two sides on flat open ground through the real turn pipeline and physics. Every lineup of `--a` fights every lineup of `--b`, and `+` joins trucks in one lineup. A truck is `driver:gear`. The driver is an NPC template, whose brain drives the truck. The gear is a start kit, an NPC template's rolled loadout as `buggy` or `buggy@heavy`, or `mg/plates+ram` for one gun and one armor on a hauler, with `bare` for no armor. A driver without gear takes its own template's loadout. To tune gear, keep the driver and vary the gear. To tune behavior, keep the gear and vary the driver. A scripted driver, `stand`, `orbit`, `charge` or `kite`, steers the player truck instead, alone on side a, to test one way of driving. `--arena 9` rings the fight with rocks 9 tiles out. The arena resumes hostility after a truce or surrender, so survivors keep fighting until a knockout or the turn limit. The ring must fit in sight, so 10 tiles at most. An arena allows 400 turns by default because evenly matched buggies took 283, versus 40 turns on open ground. It writes outcomes, hit rates and damage per pair of lineups to `tmp/combat/`, and names the side that fled. `--map fury-road:3` fights on window 0 of the Chaos Highway highway of seed 3 with Chaos Highway rules instead of flat ground, the sides lined up along the road in a stretch-1 arena just short of a scene, and the report adds `across`, the farthest any fighting truck got from the centerline, which shows whether fights use the verges. A Chaos Highway truck is a scripted driver with the kit, as `orbit:furyRoad`. `--map` and `--arena` do not mix. `--set RULES.leadError=3` changes one balance number for the run, so a tuning idea is measured before any code changes. `--trace` prints every turn.
- `npm run icons -- [--cpu] [--plans]` renders every part, good and chassis icon from the game's models in headless Chromium through the dev-only `icons.html`. It writes the sprite sheets in `public/icons/`, the condition panel's `tint.svg` and `plans.svg` in `src/ui/`, the manifest `src/data/item-icons.json`, and the labeled atlases and closest-pairs report in `public/icons/atlas/`. It fails when a weapon barrel does not read from lower left to upper right in the diagonal view. It prints each failing entry first. `--cpu` draws in software, as `playtest` does, and takes under a minute. `--plans` writes only `plans.svg`. [Art pipeline](art.md#icons) has the rules.
- `npm run quest-art -- <source image> <key>` runs the quest picture post-process and writes `public/quest-art/<key>.webp`. It needs `uv`. [Quest art](quest-art.md) has the style prompt and what the post-process does.
- `npm run stuck` is the progression recorder with a trader bot, seeds 1 and 2 and 500 turns, each seed in its own process, one at a time. It fails on any error, watchdog stall from any truck, or majority of NPCs dry at once in a world with traffic, and prints the stall with the driver's goals, order, route and neighbors. It takes about 2 minutes. Override the arguments after `--`, as for `progression:record`.
- `npm run traffic -- --seeds 1-3 --turns 300 --layer physics|far` plays a world of NPCs with the player parked and measures how fast trucks drive on the road, in km/h of the path driven each turn. The `physics` layer drives every NPC in Rapier and the `far` layer uses far travel only. It reports steady cruise per class (healthy ordinary cars, ordinary cars on low fuel, worn ordinary cars, armed and heavy roles, towing rigs) and per chassis, the causes of slow healthy samples, the low-fuel share, resupply starts, the most NPCs dry at once and collisions. It writes `tmp/traffic/<layer>-seed-<n>.json` and `tmp/traffic/<layer>.md`. Three seeds take about 13 minutes for physics at 300 turns and 10 for far at 800 turns.
- `npm run layout` boots a new game on a fixed seed and checks fourteen screens, Options and the two inspector screens among them, in English, Russian and pseudo-long text at 1280×720 and 700×800 (the inspector also at 1440×900) with `src/ui/dom.ts`. It fails on clipped text, text out of its box, sideways page scroll, overlapping or unreachable controls, missing Cyrillic glyphs and English in Russian, and on a checker that misses its planted overflowing button. It writes `tmp/layout/<screen>-<language>-<w>x<h>.png` and `tmp/layout/faults.json`. It boots one game on the GPU, hides the 3D view and switches the language live, and takes about 30 seconds. It fails when Chromium falls back to software drawing. `--cpu` draws in software, for machines without a GPU. `LAYOUT_LOCALES=ru` and `LAYOUT_STATES=shop,trade` narrow a run while you fix one screen. [Text and languages](architecture/text.md#the-layout-check) has the details.
- `npm run save:shape` records the saved shape of the current save format and the saved quest names in `src/three/save-shape.json`.
- `npm run old-spots` writes the old-world loot spot picks of the committed map to `src/data/old-spots.json`. Run it after a map rebake or a change to `OLD_PLACES`. A test fails when the file is stale.
- `npm run quests:build`, `npm run quests:check` and `npm run quest -- <quest>` build, check and play the ink quests. `npm run quest:view -- <quest>` opens the game at a quest scene. [Quests](architecture/quests.md#tools) has the flags.
- `npm run wiki` regenerates the tables in `docs/wiki/` from the code. A test fails when a table is stale or wiki prose names a data path or source file that no longer exists.
- `npm run loadouts -- --rolls 60 [--template merc] [--level heavy]` rolls many NPC loadouts per template and prints the gear level mix, mean guns, armor cover, speed kept and gear money spent. It writes `tmp/loadouts.md`.
- `npm run map:bake` builds the map from `MAPGEN.seed` in `src/data/terrain.ts` and writes `public/maps/icarus.bin`. It also writes a whole-map picture and close-ups to `tmp/map/`. A save made on another map does not load. Boot then offers to carry the player over, as [Saves](architecture/saves.md) describes, so a new map file needs no major save bump.
- `npm run perf -- --url <dev server>` boots the game in Chromium on the GPU and times boot, turns, move previews, frames over the towns by day and at night, and the per-frame work of automatic travel. It first plays 8 manual turns of a fresh game at seed 1337 and prints a seam report: the boot window's longest frame and long tasks, then per turn the wait from End turn to motion, the worker turn, the preview, the route calls, the frame p95 and max and the long tasks. The seam report has no budget. `--seams-only` stops after it. It fails on any miss against `scripts/perf-budgets.json` and when Chromium falls back to software drawing. `scripts/gpu.mjs` holds the GPU flags for the playtest, perf, icons and UI playtest scripts.
- `npm run sfx:board` opens the dev sound board for auditioning every cue.
- `npm run sfx:import -- <cue> <file...>` imports files as variants of a cue in `src/data/sounds.ts`.
- `npm run sfx:gen -- <cue> <count>` generates variants with ElevenLabs. It costs credits.
- `npm run sfx:reimport` rebuilds every sound file from the raw source path stored in its tags, after an import change.
- `npm run progression:record -- --archetypes trader,scavenger,hunter,fastTrader --seeds 1,2,3 --turns 2000` plays a bot per archetype and seed and writes each trace to `tmp/progression/` or to the `--out` directory: the XP events and one economy row per in-game day. Every bot earns, pays upkeep, buys gear and shoots back. In town it tops up the parts good to the standard kit's stock before it buys gear, so a breakdown gets a field patch. It hands its cargo to a demand, or its gear to a strip offer, only when the foe outmatches it. A bot parks when its engine reaches the heat warning and stays parked until the engine is at half of it, except in combat or with a hostile in sight. A stranded bot leaves its rescue beacon off in combat. A bot judges whether it outruns a foe by its truck's speed as it stands, so a stranded or crippled truck outruns nothing. Only the hunter seeks fights. Combat is not for a starter truck, so the hunter starts from the snowball kit unless `--kit` names another. While no raider in the world is weak enough for it to fight, it scavenges instead. It buys gear only while it keeps free the cells of the biggest part and the top speed of the fastest raider it would fight. It takes a bounty, and chases a foe it only hears, only when the foe's worst-case danger times 4 is within its own. The `hauler` takes the best haul contract on every board it reads and trades only with none, so it measures what contracts pay against open trade. The `climber` trades and buys fighting gear while keeping money for loads. Once it mounts three guns, it hunts weaker prey, accepts truces and mercy to limit repair costs, collects nearby knocked-out trucks before leaving for repairs, and trades between fights. `--kit snowball` starts from that player's convertible with four guns. The `markov` archetype plays a random one of the others and needs `--markov-turns <k>`, the turns it keeps one goal. The `escort` archetype plays a Chaos Highway world with the Chaos Highway kit and keeps beside the hauler, the way the player is meant to play. At each reached outpost it repairs both trucks, tops up their fuel and supplies and 4 parts for patching, spends a named share (`HAULER_SHARE`, 40%) of its gear money on armor for the hauler through the gear picker with the hauler job, buys the most valuable truck on offer it can afford, then buys parts for its own truck one at a time by the NPC gear scorer of a merc, best gain per M first, placed where an NPC would place them, while it keeps its upkeep reserve. It then drives a point beside the hauler, and at a paid outpost parks on the side of the pad away from the hauler, fights a hostile within 30 tiles of the hauler with the NPC fight steering of a merc, parks to patch when stranded out of combat, and ends the run when stranded with no way to patch. The `sprinter` archetype turns auto fire off and drives ahead for the next pad and never fires, so it measures whether the run can be sprinted: the hauler must lose it. `npm run escort:report` reads the `escort-<seed>.run.jsonl` and `sprinter-<seed>.run.jsonl` logs and prints, per stretch and seed, the hauler damage, its condition at the start and the end of the stretch, the player's shots and the fights, the enemy count and the useful parts the outpost stocked against the money in hand, then PASS or FAIL for each criterion: a fight in every stretch, hauler damage on most stretches, no fresh hauler lost in under 10 turns, a changing enemy mix, a real choice at the outposts, damage that rises, 6 of 10 escort seeds beating stretch 10 and every sprinter seed losing the run before it. It waits for the road after its outpost services, so it plays on the generated highway, through its hazard scenes, whose windows move under it at each outpost. Its runs end at a lost run or the turn limit, and each turn line carries the run readout as `run`: the stretch and the tiles to its outpost. A Chaos Highway run also writes `<name>.run.jsonl`: each group as it spawns, with every truck's template, chassis, guns, armor count and gear value in M's, each outpost reached with its pay, the truck's condition and the gun damage taken on the stretch, the player's money, condition and kit as it leaves each outpost with the next stretch's expected player gear, enemy gear money per truck and truck count, every beaten group truck, and at a lost run the trucks ranked by the gun damage they dealt the player in that stretch. `--kit combat` starts every run from that start kit, such as the geared combat kit, instead of the standard one. `--settings damage=2,fuelUse=1.5` starts every run with those [world settings](wiki/mechanics/world-settings.md), each missing one at its default, and a bad value fails the run. The world is Roaming but for the `escort` and the `sprinter`, which play Chaos Highway. The recorder runs headless by default, so every truck uses the cheap far rules. `--physics true` moves the trucks near the player by the game's physics instead, as the browser does, so rams, crashes, hazard scenes and close fights play out for real. Use it for the `escort`, where fights decide the run. Runs go one at a time. A run that hits an error ends with an error line, the next run starts, and the batch fails at the end. A 30-day run takes about 18 minutes, so run it in the background with a log.
- `npm run progression:report` replays every trace in `tmp/progression/` with the current XP rules. It prints the days each activity family's XP covers each rank's cumulative cost, the XP per day per archetype and misses against the targets in `src/data/skills.ts`. It also prints, per archetype, the wage per turn at each gear tier, the first day each tier is held, and the fights won, knockouts, gear lost and deaths of each seed, net worth by day split into money, cargo, gear, storage and chassis, and money by ledger key. Net worth counts truck damage at its repair bill. Goods a haul contract carries are not counted, so accepting and delivering a haul moves net worth only by what it pays. A last summary prints one line per bot with profit per turn, net worth gained per turn and its ratio to the trader. Profit is every ledger key but gear, so it measures the work and not the shopping. Goods still aboard at the end count as spent. Pass a directory after `--` to report on traces elsewhere. Pass two directories to compare them: each bot's summary on side A and side B, and the change in money per day by ledger key.
- An A/B test checks a balance change before it goes into `src/data/`. Write a patch module that imports a data file and changes a number in place, such as `DISTANCE_PREMIUM.perTile *= 2`. Record the same bots, seeds and turns twice, once plain into one `--out` directory and once with `--patch <file>` into another, then report on both directories. A number a data file derives from another at load time does not follow the patch, so patch it as well. The report says so when both sides end on the same net worth.
- `npm run progression:watch -- --archetype trader --seed 1 --from 4500 --to 5000` plays one run and prints the player truck turn by turn: money, net worth, goods, contracts, order, part HP and the events that touch the player. Use it to see why a number in the report looks wrong.
- `npm run progression:playthrough -- --seed <n> --turns <n> --out <file> [--archetype markov] [--every 50] [--sha <sha>]` plays one progression run and writes its full activity log: every game event, a snapshot of the player and every NPC every `--every` turns, how the run ended, and a summary. `--archetype` defaults to `markov` and `--sha` to none. Every truck uses the cheap far rules, as in the recorder. The factory's release playtest reads the log. The log goes to a part file that is renamed when the run ends. A bad argument exits 1. An in-game error or stall ends the log with an error line and exits 0.
- Beside each trace the recorder writes two logs for analysis by plain file reads. `<bot>-<seed>.turns.jsonl` has one line per turn: the player truck's position, money, net worth, fuel, parts with health, goods, contracts, order, flags, the hostiles in sight with the player's odds to win against each and their speed, the money moved by kind, and every event that touches the player. The recorder throws when the player's or any NPC's money changes by more than that turn's money events explain. `<bot>-<seed>.world.jsonl` has every event of every turn raw, whoever it touches, each NPC's money moved that turn by kind, and a snapshot of every truck every 10 turns with its money, fuel, supplies, goals and states, whether it is stranded, whether it keeps off roads, whether it stands on one and its gap to the nearest road edge. A 5-day run writes about 7 MB. `npm run progression:analyze -- tmp/<dir>` sweeps a batch for every kind of trouble at once: time spent in combat, stranded or towed, each fight with the foes and the outcome, with the player's odds against each foe and its speed from the turn it first appears, combat stretches with no shot fired as one standoff line, each big loss with the events before it, tows, stalls, debt, dry tanks, flapping rules, the population per faction, how often raiders that keep off roads are on one against healthy raiders with a miss when hunting raiders are on a road more than 25% of the time, the share of hunting raiders within 6 and 10 tiles of a road, the raiders' `preyPassed` reasons and the raider fights begun from a raid, a patrol or an investigation, every lost truck, and NPC solvency by role: broke, starving and stranded counts at each day end, start cash, the median net money per NPC-day and the mean flow by kind over days 1 to 5, the trucks that starved at any snapshot, lie-ups, escort hires and guard pay. Mine a batch fully before rerunning anything.
- `npm run income -- --seeds 1-6 --days 2 --policy robber,convoyRobber,trader,scavenger --jobs 3 --candidate A` plays each policy on the `midgame` start kit, every skill at rank 2 and no gear bought, through the real turn pipeline with every truck on far travel, one process per seed and policy. `robber` demands cargo from traders and convoys it sees carrying cargo with no escort in sight, and patrols Bowl and Nose. `convoyRobber` also takes on guarded convoys, and patrols the sites supply convoys haul between. Each run writes `tmp/income/<candidate>/<seed>-<policy>.json` (`--out` sets the folder) with the candidate name and the build: the last commit that changed non-test code in `src/`, plus a hash of any uncommitted change there. A run whose file exists for the same build is skipped, and one for another build fails the batch. Every 30 turns a run samples the world: the hauling margin index (the best load for 2000 money and 20 cells between two towns, less its fuel), the salvage price index (the mean town sell price of goods), and each awake trader and convoy's wallet, escort, cargo value and whether the robber would take it, sight aside. It also counts NPC knockouts and tows per day. The batch writes `report.md` in the folder with net worth per in-game hour, daily percentiles, robbery attempts by target and answer, and wallets by day. It throws when a run's money ledger does not match its money change. A 2-day run takes about 10 minutes of one CPU core, and several times that on a loaded host.
- `npm run income -- --report tmp/income/A --baseline tmp/income/baseline` writes only the report: the gate report of issue 157 (G1 to G7, with the robber and hauler paired by seed and the 80% interval of their difference) and the run tables. The gate thresholds are constants in `src/sim/progression/income-report.ts`, and a gate fails loud on runs of mixed builds.
- `npm run itch` builds the game and uploads it to itch.io with butler. It builds the last commit in a clean worktree and names the upload after it. [Publishing](publishing.md) has the one-time setup.

## Config

`src/config.ts` holds the world seed, start kit, combat playback times, save interval, Space hold delay and travel speed multiplier. The world seed drives sim randomness, like where the first NPCs start, but not the map. A null seed rolls a new one for each new game, and the save keeps it. `.env` holds `ELEVENLABS_API_KEY` and `SFX_MAX_GENERATIONS` for sound generation and `ITCH_TARGET` and `BUTLER_API_KEY` for publishing.

## Browser checks

A browser check is for what the screen shows: UI, rendering and screenshots. Playtest game behavior with the progression recorder instead. Drive the game with a Playwright script in `tmp/`. Launch Chromium with `gpuArgs()` from `scripts/gpu.mjs`, so it renders on the real GPU on a Mac and on Linux. SwiftShader renders on the CPU at 10 to 20 fps, so its frame rate says nothing about the game. The game is on `window.__ROAM__` in dev. Its world is `__ROAM__.state`, and `__ROAM__.language.set('ru')` switches the language. The game starts on the start menu, which a script cannot pass on its own, so open it with `playUrl()` from `scripts/game-url.mjs`. That adds `?play`, which in dev skips the menu and loads the newest save or starts a new game without the intro. A production build ignores `?play`, so `boot:time` writes a boot request into session storage instead. In dev, `?seed=<n>` gives a new game a fixed seed, and `?lang=pseudo` shows English padded by 40% to find layouts that break on longer text. `?lang=ru` and `?lang=en` open that language for the visit without storing it. To set up a situation, clone that world, edit it, and pass it to `apply()`. `debugScreenOf(x, y)` gives the screen point of a map point on the ground, for clicks. `node scripts/garage-ui-check.mjs <url>` checks the garage: mouse and keyboard selection drives the shop comparison, the garage header and repair bar labels, and the layout at 1920, 1600, 1280, 1024 and 800 wide, including that every truck card on the Trucks tab holds its stats, map and Swap button and that the shop never scrolls sideways. `node scripts/sound-decode-check.mjs <url>` runs `sound-check.html` through a caching proxy in Playwright Chromium, Firefox and WebKit: every sound decodes, a cached truncated `hit-metal-2.ogg` is replaced by the real buffer, and an injected decoder fault is recovered after boot. WebKit does not reuse the cached bad copy, so its second case passes without the retry. `node scripts/shop-parts-check.mjs <url>` checks the compact shop part rows: collapsed by default, one open at a time, keyboard, purchase, filter and narrow layouts, with screenshots in `.playtest/`.

`npm run site:shot -- <site-id>[,<site-id>] [--hour 23[,12]] [--zoom 1] [--out .playtest/sites] [--url http://localhost:5173]` teleports the truck to each site's first pad, sets the hour and saves one screenshot per site and hour. It fails on any browser error.

The game camera has a fixed bearing, so a shot of a face it does not show needs the camera turned from the script. The rig sets the camera at its fixed offset every frame, so wrap the instance's `tick` on `__ROAM__.rig`: call the original, then move `rig.camera.position` around `rig.center` to the bearing and elevation wanted at the same distance, and `lookAt(rig.center)`. The turn is script-only and never touches game code.

## Debugging

- In dev, any uncaught error shows a fullscreen crash screen with the message. Outside dev, errors after boot go to the browser log and the debug console, and the game keeps running. Boot errors always show the crash screen. A browser that cannot create a WebGL 2 context gets a notice that names the fixes instead, and the error reporter does not send it. Boot downloads (models, map, sounds) retry a dropped request or an HTTP 404, 408, 429 or 5xx up to six times, waiting 0.5, 1, 2, 4 and 4 seconds between tries. When a file still cannot download, the game shows a notice with a Reload button that tells the player to check the connection, and the error reporter does not send it. A file still missing after the tries (404) shows the crash screen and is reported, except a map prop model, which gets a grey box stand-in and a report. The crash screen lists the error, its source file, line and stack when known, the game version, the boot step, the browser and the page address without its query, so a player can post a screenshot of it. It shows no save content. A hidden "Script error." with no error object, from a script outside the game such as a browser extension, never crashes and never holds saves. It goes to the browser log and once to the debug console, since the game's own code loads as same-origin modules whose errors browsers never hide. A failed turn does not play: the log shows it, automatic turns stop, and no save is written until a turn completes without an error.
- The factory's release, dev and candidate builds also send every error to the factory's error endpoint, set by `ERROR_REPORT_URL` at build time. `src/three/error-report.ts` sends each distinct error once per session, with the game context and, for a failed turn, the physics drive the turn started from. A build without the URL sends nothing.
- The game context is the same in error reports and in the report form: the version, the browser, the language, the screen size, the turn, the log, the world in memory and the Autosave. `GameContext` in `src/three/error-report.ts` builds it. The report form takes the world when the player presses send, so the report holds the game as the player saw it. Neither report writes a save slot. `factory/src/error-reports/report.ts` checks the same shape, so change both together. The form says a report is sent, failed or over the factory's hourly cap. A 429 shows the minutes until the cap resets from the answer's `retryAfterSeconds`, so the player waits instead of retrying.
- `npm run error:replay -- <report.json.gz>` loads the world of an error report or a player report headless, runs its turn and prints what it throws. Run it on the report's commit. `--from autosave` starts from the report's Autosave. Only a failed turn's error report reruns exactly, since only it holds the physics drive.
- The backquote or § key opens the debug console in every build. Type `help` for its cheat commands. `src/ui/console.ts` parses the commands and calls one pure function per cheat in `src/sim/cheats.ts`. Bad input throws `CheatError`, which the console prints. Any other error reaches the crash screen. God mode is a saved player flag. It restores the truck in `endTurn` before the destruction and defeat checks.
- `src/perf.ts` holds named timers for seams, never hot loops, and merges the measurements of the turn worker and the preview worker into the main counters. The console command `fps` shows them in a panel in the top left.
